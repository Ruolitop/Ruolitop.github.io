从表中随机返回 n 行数据

问题：你想从表中随机返回 n 行数据，例如修改 select ename, job from emp，使其返回 5 行数据，且每次执行时返回的行都不同。

关键函数与语法要点

  • ORDER BY rand() limit 5：先随机排序，再取前 5 行；由于排序是随机的，每次执行返回的行都不同。
  • ORDER BY 中指定函数与指定数值常量导致的排序方式不同：指定数值常量时，要求根据 SELECT 子句中相应位置的列进行排序；指定函数时，要求对每行执行该函数，并根据函数的结果进行排序。
  • 这些方案都在 ORDER BY 子句中的函数执行后再限制返回的行数。

合并多个行集

问题：你想返回存储在多张表中的数据，即将多个结果集合并；这些表并非必须有相同的键，但它们的列的数据类型必须相同。例如同时显示 EMP 表中部门编号为 10 的员工的姓名和部门编号，以及 DEPT 表中每个部门的名称和编号。

解决思路：通用写法，MySQL 亦适用。使用集合运算 UNION ALL 合并来自多张表的行，它可以将来自多个数据源的行合并为一个结果集。与所有的集合运算一样，在 SELECT 子句中指定的列的数量和类型必须匹配，否则查询将以失败告终。

运行结果

关键函数与语法要点

  • UNION ALL：把多个结果集的行合并为一个，且不剔除重复的行，是默认首选写法。

提取姓名中的首字母

问题：你想将全名转换为首字母缩写，例如把 Stewie Griffin 返回为 S.G.。

解决思路：SQL 不像 C 或 Python 等语言那么灵活，创建能处理任何姓名格式的通用解决方案并非易事；本解决方案要求全名要么由名和姓组成，要么由名、中间名/中间名缩写和姓组成。MySQL 使用内置函数 CONCAT、CONCAT_WS、SUBSTRING 和 SUBSTRING_INDEX 提取首字母。

关键函数与语法要点

  • SUBSTRING_INDEX(str, delim, n)：按分隔符切分并提取第 n 段；n 为正数从左往右、为负数从右往左，因此 substring_index(name,' ',1) 取名、substring_index(name,' ',-1) 取姓。
  • SUBSTR(str, pos, len)：取首字母用 substr(...,1,1)；取中间名首字母的起点是 length(substring_index(name,' ',1))+2，即先找到名的末尾，再向前移动两个字符到达中间名或中间名缩写的开头。
  • CONCAT_WS('.', ...)：以句点为分隔符拼接各个首字母，函数名中的 WS 即「with separator」。
  • TRIM(TRAILING '.' FROM ...)：剔除首字母缩写末尾多余的句点（S.G.. → S.G.）。
  • LENGTH(name)-LENGTH(REPLACE(name,' ',''))：用长度差统计空格个数，即姓名由几部分组成，结果存入 cnt；cnt = 2 时说明只有名和姓，执行 CASE 的 ELSE 分支。
  • 内嵌视图 Y 负责删除姓名中所有的句点（处理中间名缩写），内嵌视图 X 负责确定姓名中有多少个空格，以便决定调用 SUBSTR 的次数。

其他写法：仅由名和姓组成的姓名，可以省去 CASE，直接用 CONCAT_WS 拼接两个首字母。

运行结果

这种写法只处理「名 + 姓」，且结果会多出一个末尾句点（S.G..），需要像主方案那样用 TRIM(TRAILING '.' FROM ...) 剔除。

  • 本书提示在 DB2、SQL Server 和 PostgreSQL 中，若 SAL 列是整型，需要显式 CAST(... as decimal) 才能保证除法得到小数；MySQL 的 / 运算符本身返回小数结果，一般无需额外 CAST。
  • 书中该小节的窗口函数写法（sum(sal)over() 求总计、sum(sal)over(partition by deptno) 求部门小计）标注为 DB2、Oracle 和 SQL Server 方案；MySQL 8.0 也支持窗口函数。
  • 通用原则：窗口函数在 WHERE 子句之后执行，因此基于 DEPTNO 的过滤器不能放在内嵌视图中，否则 TOTAL 会退化为 10 号部门的薪水总额（8750）而非全表总额（29025），必须把过滤放在内嵌视图外面。

将由字母和数字组成的字符串转换为数字

问题：有一列由字母和数字混合组成的字符串，只想返回其中的数字，例如从 paul123f321 中取出 123321。

解决思路：本书给出的方案是以函数 TRANSLATE 为核心，先把字符串中的非数字字符统一映射为 #，再用 REPLACE 删除所有 #，最后用 CAST 把结果作为数字返回。DB2 使用 REPEAT('#',26) 生成占位符串且 TRANSLATE 的参数顺序不同；Oracle、SQL Server 与 PostgreSQL 使用 RPAD('#',26,'#')。源文本明确说明：本书撰写之时 MySQL 不支持函数 TRANSLATE，因此没有提供 MySQL 解决方案。

关键函数与语法要点

  • TRANSLATE(str, from, to)：按字符逐一映射，把 from 中出现的每个字符替换成 to 中对应位置的字符；MySQL 未提供该函数。
  • REPLACE(str, from, to)：删除映射后留下的占位符 #，MySQL 支持。
  • CAST(expr AS type)：把清洗后的字符串转换为数字，MySQL 支持（也可用 CONVERT）。
  • RPAD('#',26,'#') / REPEAT：用与原字符串长度相同的 # 串做占位符，因为任何字符在一个字符串中出现的次数都不会超过该字符串的长度。

MySQL 说明：本书该小节仅给出 DB2、Oracle、SQL Server 与 PostgreSQL 解决方案，未提供 MySQL 实现。MySQL 没有 TRANSLATE；若需要同样的效果，可在 MySQL 8.0 中用 REGEXP_REPLACE 之类的方式剥离非数字字符，但源文本未给出此类写法。

使用绝对中位差找出异常值

问题：你想找出数据集中可能存在疑问的值（仪表误差、数据输入错误、环境异常等都可能导致可疑数据）。

解决思路：整体策略是先按 7.10 节的办法求出中值，再求「各值与中值的绝对偏差」的中值，即绝对中位差（MAD），最后用每个值相对中值的偏差除以 MAD，像使用标准偏差那样使用这个比值。MySQL 没有提供函数 MEDIAN 或 PERCENTILE_CONT，求中值时需要自己用累积分布实现：对 sal 排序取累积分布 >=0.5 与 <=0.5 的最多两行求平均得到中值，把中值放进 CTE 后再对偏差重复同一过程，因此代码比其他数据库长些。

关键函数与语法要点

  • WITH CTE：用 rank_tab、inter、medianSal、deviationSal、distDevSal、DevInter、MAD 一步步串起中值、偏差与绝对中位差的计算；MySQL 8.0 起支持公共表表达式。
  • cume_dist() over (order by ...)：返回累积分布值，用它筛出分布中位附近的行，是 MySQL 中替代 MEDIAN/PERCENTILE_CONT 求中值的办法。
  • UNION：把「累积分布 >=0.5」与「<=0.5」两个分支合起来，偶数个值时取两行的平均作为中值。
  • abs(sal - 中值)：偏差定义为中值与各个值的绝对差；对偏差再取一次中值即得绝对中位差。
  • 异常判定：一个值相对中值的偏差超过绝对中位差的 3 倍以上，即可认为它是异常值；薪水数据中唯一越界的正是 CEO 的薪水。
  • 相比标准偏差的优点：数据不呈正态分布（例如分布不对称）时，绝对中位差依然给出合理答案，属于非参数统计工具。

使用本福特法则查找反常数据

问题：你想检测不像异常值那样明显的反常数据——查看数字位的出现频率，并将其与本福特法则（Benford’s Law）预测的频率比较，常用于检测数据造假、重复数据点等错误。

解决思路：通用写法，MySQL 8.0 亦适用。先计算数字位的期望分布，再与数据的实际分布比较：用 LEFT(CAST(SAL AS CHAR),1) 取出首位数字并计数，用 t10 透视表生成 1–9 的期望频率，再右连接两者以便把实际计数为 0 的位组合也显示出来。最复杂的本福特法则用法会考虑第一位、第二位以及数字位组合，本例只考虑前几位。结果集包含 4 列：第一位的预测频率、第一位的实际频率、前几位的预测频率、前几位的实际频率。

关键函数与语法要点

  • LEFT(cast(SAL as CHAR), 1)：先转成字符串再取首位数字；等价的 SUBSTRING(str, 1, 1) 写法源文本未给出。
  • LOG10(ID + 1) - LOG10(ID)：本福特法则的期望频率计算式，t10 提供 1–9 的序号。
  • RIGHT JOIN 配合 CTE ExpectedBenford：即使实际数据中某个首位数字没有出现，也把该位组合保留在结果中。
  • COALESCE(count(*)/Total, 0)：右连接产生的无匹配行计数为 NULL，用 COALESCE 显示为 0。
  • 讨论段说明，也可以只在主查询中生成 FirstDigits 计数，之所以拆成 CTE，是为了不在 GROUP BY 子句中重复书写 LEFT(CAST...) 表达式，从而提高可读性。
  • 适用条件：数据集相对较大、其中的值跨越多个数量级（10、100、1000 等）时本福特法则效果最好。

无法确认：讨论段称「本福特法则使用的数学公式很简单」，但抽取文本中没有给出该公式的完整表述，仅能由 SQL 中的 log10(ID + 1) - log10(ID) 推知其形式。

11.11 查找马值

问题：你想返回一个结果集，其中包含每位员工的名字、所属的部门、薪水、获聘日期，以及所属部门最后聘请的员工的薪水。

解决思路：这类值被称为马值（knight value）：先跳到某一行（当前部门中最后的 HIREDATE 所在行），再跳到某一列（该行的 SAL），与确定国际象棋中马的下一个位置的方式类似。本书给出的做法是先用窗口函数 MAX OVER 找出每个部门最后获聘的员工：DB2 和 SQL Server 在子查询中用 CASE 表达式把该员工的 LATEST_SAL 设为其 SAL、其他员工设为 0，外层再用 MAX OVER 取部门内的非零值；Oracle 则在 KEEP 子句中用 DENSE_RANK 和 LAST、按 HIREDATE 排序直接返回最后获聘员工的 SAL。

关键函数与语法要点

  • MAX ... OVER (PARTITION BY ...)：在分区内求最大值，书中用它定位部门最后获聘的日期、并汇总部门内的非零 LATEST_SAL。
  • CASE 表达式：在子查询中把「最后获聘」这一行之外的 LATEST_SAL 置为 0。
  • KEEP (DENSE_RANK LAST ORDER BY HIREDATE)：Oracle 专有语法，用于「按一个维度排名、对另一个维度聚合」。
  • 以窗口函数实现本实例时不需要连接和内嵌视图，这是书中所强调的便利之处。

MySQL 说明：本书该小节仅给出 DB2、SQL Server 和 Oracle 解决方案，未提供 MySQL 实现。需注意 MySQL 8.0 已支持窗口函数（含 MAX() OVER (PARTITION BY ...)），但 KEEP (DENSE_RANK ...) 子句在 MySQL 中不存在。

关键函数与语法要点

  • ROW_NUMBER() OVER (ORDER BY empno)：按 EMPNO 排序并为每一行指定一个排名（行号）。
  • CEIL(x)：返回不小于 x 的最小整数，确保分组号是整数；MySQL 使用 CEIL（SQL Server 为 CEILING）。
  • 除以 5.0 而不是 5：让除法明确保留小数部分（.2、.4、……），向上取整后才能得到正确的桶号。逻辑上相当于把行分成规模为 5 的编组：5 个值 ≤ 1，接下来 5 个值 > 1 且 ≤ 2，以此类推。

12.8 创建预定数量的桶

问题：想把数据划分到数量固定的几个桶中，例如把 EMP 表中的员工划分到 4 个桶。此时桶数已知，但每个桶中的元素个数可能未知。

解决思路：通用写法，MySQL 8.0 亦适用。由于现在很多关系数据库都支持函数 NTILE，解决方案很简单：NTILE 会把一个有序集合划分到指定数量的桶中。如果集合元素无法均分，多出来的元素放到前面的桶中——本例第 1 个和第 2 个桶各有 4 行，第 3 个和第 4 个桶只有 3 行。

运行结果

关键函数与语法要点

  • NTILE(n) OVER (ORDER BY ...)：ORDER BY 子句按指定顺序排列行，NTILE 本身给每一行指定一个组号，把前 1/4 的行加入第 1 组，接下来 1/4 加入第 2 组，以此类推。
  • 余数分配规则：无法均分时，多出来的元素分给靠前的桶（第 1、2 桶 4 行，第 3、4 桶 3 行）。
  • 本问题与 12.7 正好相反：12.7 中桶的数量未知但每桶元素个数固定；本节中每桶元素个数未知但桶数固定。
  • 分桶的价值：先分成规模相同的集合，再计算各桶的平均薪水等指标，可以揭示查看单个值时会波动掩盖的趋势。

MySQL 说明：NTILE 是窗口函数，MySQL 8.0 起支持；MySQL 5.7 及更早版本没有 NTILE，本节没有其他对应写法。

12.12 计算简单的小计

问题：你想创建一个结果集，既包含小计（对分组列聚合），又包含总计（对整张表聚合），例如按职位（JOB）给出薪水小计，再给出 EMP 表中所有薪水的总计。

解决思路：（通用写法，MySQL 8.0 亦适用）使用窗口函数 COUNT OVER，并指定要进行聚合的数据分区（分组）。只需指定要聚合的各种数据分区，就能制作非常详细的报表，既不需要反复自连接，也不需要在 SELECT 列表中编写烦琐（还可能性能低下）的子查询。

运行结果

关键函数与语法要点

  • count(*)over(partition by deptno)：按 DEPTNO 划分数据分区，PARTITION BY 找出所有唯一的 DEPTNO 值（10、20、30），COUNT 统计包含该 DEPTNO 值的行数，分区内每一行都得到同一个计数。
  • count(*)over(partition by job)：同一个窗口函数换用 JOB 分区，工作原理完全一样。
  • count(*)over()：括号内为空表示「整张表」，计算 EMP 表的总行数。
  • OVER 子句的主要部分是 PARTITION BY（指定分区依据）与 ORDER BY（指定逻辑顺序）；没有指定框架或窗口子句（没有 ORDER BY）时，计算的是每个分组的全部行数。
  • 窗口函数在 WHERE 子句之后执行：若先过滤掉 10 号部门的员工，TOTAL 将为 11 而不是 14；若想在窗口计算之后再过滤结果，必须把窗口查询放进内嵌视图，再对外层结果过滤。

12.20 转置包含小计的结果集

问题：想制作一张包含小计的报表，再对其进行转置，使报表的可读性更强——列出每个部门、每个部门的管理者以及各管理者下属员工的薪水总和，并返回部门小计与全部薪水总计。

解决思路：先用 GROUP BY 扩展 ROLLUP 生成小计，再执行经典转置操作（使用聚合和 CASE 表达式）生成所需的报表列；用函数 GROUPING 可以轻松确定哪些值是由 ROLLUP 生成的小计。根据 RDBMS 对 NULL 值的排序方式，可能需要在解决方案中添加 ORDER BY，让最终输出与目标结果集一致。这里是 MySQL 的写法。

运行结果

关键函数与语法要点

  • group by deptno,mgr with rollup：MySQL 的 ROLLUP 写法，在按部门与管理者分组的基础上追加每个部门的薪水小计和全体员工的薪水总计（只用有管理者管理的员工计算）；DB2 与 Oracle 的等价写法是 group by rollup(deptno,mgr)。
  • grouping(deptno)：MySQL 8.0 的 GROUPING 函数，某列的值由 ROLLUP 补 NULL 时返回 1，是常规分组值则返回 0。
  • concat(cast(grouping(deptno) as char(1)), cast(grouping(mgr) as char(1))) flag：把两个 0/1 拼成位映射（bitmap）。各平台方案的唯一差别就在这里——MySQL 用 concat，SQL Server 用 +，DB2 与 Oracle 用 ||。

  • sum(case deptno when 10 then sal else 0 end) dept10：经典转置写法，管理者在某个部门没有下属时返回 0；sum(case flag when '11' then sal else null end) total 用 null 而非 0，保证只有总计行参与求和。
  • order by coalesce(mgr,9999)：书中的 SQL Server 方案用它把总计行排到最后。MySQL 方案未包含排序，而 MySQL 中 NULL 默认排在最前，若想得到书中报表的顺序需自行加上排序。

问题：返回一个把整张表的层次结构呈现出来的结果集。EMP 表中 KING 之上没有管理者，因此 KING 是根节点；要从 KING 开始显示其所有下属以及这些下属的所有下属。

13.5 确定叶子节点、分支节点和根节点

问题：判断给定的行属于哪种节点类型——叶子节点（不是管理者、没有下属的员工）、分支节点（自己是管理者且还有上级管理者的员工）、根节点（没有上级管理者的员工）；对层次结构中的每一行返回 1（TRUE）或 0（FALSE）以指出其状态。

解决思路：EMP 表建立的是树型层次结构而不是递归层次结构，因为根节点的 MGR 为 NULL；处理树型层次结构比处理递归层次结构更容易、效率也更高。DB2、PostgreSQL、MySQL 和 SQL Server 共用同一方案：使用 3 个标量子查询在每个节点类型列中返回正确的「布尔」值（1 或 0）。

运行结果

13.6 小结

现在所有 RDBMS 都支持 CTE，这使得编写适用于各 RDBMS 的分层查询比以前容易得多。鉴于很多数据都包含层次关系，而查询时必须考虑这种关系，CTE 的面世是个巨大的进步。

14.9 给经过两次转置的结果集添加列标题

解决思路：本解决方案基本上只是执行了合并和转置，再做细微调整：在每个部门的员工 ENAME 前面加上相应的 DEPTNO。这里使用笛卡儿积（Cartesian product）为每个 DEPTNO 多生成一行数据，以便同一个部门既显示编号、又显示该部门的全部员工；最后按移动总计分组，把两部分转置成并排的两列。书中该方案以 Oracle 语法给出（用 DECODE 把值分派到不同列），并说明由于 DB2 支持计算移动窗口的窗口函数（框架子句），很容易改写成 DB2 版本。

MySQL 说明：本书该小节仅给出 Oracle 解决方案（仅附带「易于改写为 DB2」的说明），未提供 MySQL 实现。若要在 MySQL 8.0 中实现同样的报表，需做以下替换：DECODE 在 MySQL 中没有对应函数，改用 CASE（最终靠 CASE 聚合加别名给两列加标题）；ROW_NUMBER() OVER (PARTITION BY ...)、COUNT(*) OVER (...) 与 SUM(...) OVER (...) 在 MySQL 8.0 中可直接照用；connect by level <= 2 这种「生成两行」的写法在 MySQL 中需改用 WITH RECURSIVE 或数字辅助表；ROWNUM 在 MySQL 中不存在，需另找定序依据。

14.11 将序列化数据转换为行

问题：分析存储在字符串中的序列化数据，并把其中的值作为行返回——例如把 entry:stewiegriffin:lois:brian: 这样的字符串拆分为 VAL1、VAL2、VAL3 三列。

解决思路：每个序列化字符串最多存储 3 个值，值之间用冒号分隔，也可能少于 3 个；值不足时必须小心处理，把各个值放到结果集正确的列中（例如 entry:::flanders: 缺失前两个值，因此 FLANDERS 所在行的 VAL1 与 VAL2 都是 NULL）。解决方案的关键是先分析字符串，再执行简单的转置：先生成 100 行的笛卡儿积遍历每个冒号位置，用 INSTR 确定每对冒号的位置与待取值的长度（别名 P1、P2），再用 SUBSTR 提取冒号之间的值，最后对结果应用聚合函数并按 STRINGS 分组，让结果集易于阅读；文中说明这是 Oracle 写法，但由于只涉及字符串分析函数，很容易改写成其他 RDBMS 的版本。

MySQL 说明：本书该小节仅给出 Oracle 解决方案，未提供 MySQL 实现。移植要点：connect by level <= 100 生成行序列在 MySQL 中需改用 100 行的数字辅助表（书中其他地方称透视表（pivot table）T10）或 WITH RECURSIVE；INSTR(strings,':',1,id) 对应 MySQL 的 LOCATE()／INSTR()，SUBSTR(strings,p1+1,p2-1) 对应 SUBSTRING()（参数含义一致）；DECODE 需换成 CASE。MySQL 中另一种常见写法是直接用 SUBSTRING_INDEX(SUBSTRING_INDEX(strings,':',n),':',-1) 取出第 n 段的值；MySQL 8.0 还可用 JSON_TABLE() 把 JSON 数组展开为行（需先把字符串转成 JSON）。以上写法均为原书之外的补充提示。

关键函数与语法要点

  • INSTR(v.strings,':',1,c.id)：返回第 c.id 个冒号在字符串中的位置，别名 p1；INSTR(...,c.id+1)-INSTR(...,c.id) 得到两个冒号之间的长度，别名 p2。
  • SUBSTR(strings,p1+1,p2-1)：从 p1 的下一个字符开始取 p2-1 个字符，正好是两个冒号之间的值。
  • DECODE(id,1,...,2,...,3,...)：按笛卡儿积返回的 ID（1、2、3）把值分派到 VAL1／VAL2／VAL3；某个字符串值不足 3 个时，对应列自然为 NULL。
  • MAX(...) 配合 group by strings：把同一个字符串产生的多个中间结果折叠成一行，即最后一步「聚合让结果集便于阅读」的做法。
  • where c.id <= (length(v.strings)-length(replace(v.strings,':')))-1：用「冒号总数减 1」限定需要遍历的段数，避免生成多余的行。

14.12 计算占总计的百分比

问题：制作一张报表，呈现每个值占总计的百分比——例如薪水在不同职位之间的分布，用来确定哪种职位给公司带来的开销最高，同时还要呈现各职位的员工数量以免误导。

解决思路：先用窗口函数 COUNT(*) OVER (PARTITION BY job) 返回各职位的员工数量 NUM_EMPS，再用 RATIO_TO_REPORT(sal) OVER () * 100 返回每位员工薪水占薪水总计的百分比（返回的是小数），最后按 JOB 和 NUM_EMPS 分组，用 SUM(ROUND(pct)) 把同一职位各员工的百分比相加，得到该职位占总计的百分比。乘以 100 后返回的是表示百分比值的整数（占比 25% 时返回 25 而不是 0.25）。解决方案段明确指出：仅当使用 Oracle 时，才能用内置函数 RATIO_TO_REPORT 妥善解决该问题。

MySQL 说明：本书该小节仅给出 Oracle 解决方案，未提供 MySQL 实现；RATIO_TO_REPORT 是 Oracle 专有窗口函数，MySQL 8.0 没有这个函数。原书指出在其他 RDBMS 中计算占总计的百分比应使用除法运算，并指向 7.11 节「计算总计占比」——该节的 MySQL 方案见本笔记 c07a.md 的 7.11 小节（用 CASE 挑出目标范围的薪水，除以总计后乘 100）。MySQL 8.0 也支持窗口函数，可写成 SUM(sal) / SUM(SUM(sal)) OVER () 这类形式（原书未给出该写法）。

关键函数与语法要点

  • RATIO_TO_REPORT(sal) OVER ()：Oracle 专有窗口函数，返回某个值占窗口内总计的比例；MySQL 中没有，用「值 ÷ 总计」的除法或窗口函数实现。
  • COUNT(*) OVER (PARTITION BY job)：为每一行附上其所属职位的员工数量，得到 NUM_EMPS，无需额外连接或标量子查询。
  • SUM(ROUND(pct)) 配合 group by job,num_emps：把同一职位各员工的百分比相加，得到该职位占总计的百分比；务必同时按 JOB 和 NUM_EMPS 分组。
  • 乘 100 与 ROUND 的作用：把小数比例转成整数百分比，便于阅读。
  • 呈现 NUM_EMPS 的意义：PRESIDENT 只有 1 人，只看百分比容易低估其开销，加上人数后可以看出总裁一个人的薪水就占了总薪水的 17%。

14.13 确定编组是否包含指定的值

问题：对给定的行创建一个布尔标志，指出在该行所属的编组中是否至少有 1 行包含特定的值——某学生在 3 个月（一个学期）内的 3 次考试中只要通过一次即满足要求，若一次都没通过，则要在该学期最后一次考试所在行把 IN_PROGRESS 置为 1。

解决思路：难点在于必须把编组中的行作为一个整体来处理，不能逐行评估。由于 PASS_FAIL 列的值只能是 1 或 0，使用窗口函数 MAX OVER 就能轻松确定某位学生在特定学期内是否至少通过了一次考试（组内最大值为 1 即表示有通过）；再用窗口函数 MAX(test_date) OVER 找出每个学期最后一次考试的日期，最后用 CASE 表达式（书中用 Oracle 的 DECODE）生成 METREQ 与 IN_PROGRESS 列，并用 LPAD 让 METREQ 的值右对齐。书中提醒：示例行是用 Oracle 语法生成的，使用其他 RDBMS 时必须做细微修改。

MySQL 说明：本书该小节仅给出 Oracle 解决方案，只提示其他 RDBMS「需做细微修改」，未提供 MySQL 实现。MySQL 8.0 支持窗口函数，核心的 MAX(pass_fail) OVER (PARTITION BY student_id,grade_id,period_id) 与 MAX(test_date) OVER (...) 可以原样照用，LPAD() 在 MySQL 中同样存在；需要替换的是 DECODE → CASE，以及示例视图中的 to_date('02/01/2020','MM/DD/YYYY') → STR_TO_DATE(...)、Oracle 的 dual → MySQL 中可省略 FROM。另外，判断编组是否包含指定值也可以先按编组 GROUP BY，再用 HAVING 比较 MAX(pass_fail)（或对 pass_fail = 1 计数），但原书未给出这种写法。

关键函数与语法要点

  • MAX(pass_fail) OVER (PARTITION BY student_id,grade_id,period_id)：编组内只要有 1 行通过就返回 1，等价于「该编组是否包含指定值」；窗口函数让每一行都能看到整个编组的结果，无需自连接或额外的分组查询。
  • MAX(test_date) OVER (PARTITION BY student_id,grade_id,period_id)：取每个学期最后一次考试的日期，用于定位应把 IN_PROGRESS 置为 1 的那一行。
  • DECODE(grp_p_f,1,lpad('+',6),lpad('-',6))：按编组是否通过生成 +／-，并用 LPAD 补足 6 位实现右对齐（DECODE 可用 CASE 替代）。
  • DECODE(test_date,last_test,1,0)：只有当该行是本学期最后一次考试时才可能返回 1，其余为 0；若学期内已通过考试，外层直接固定为 0。

A.1.1 SQL 分组的定义

A.1.2 悖论

GROUP BY 子句中可指定的值种类繁多（常量、表达式，最常见的是列），而 NULL 在 SQL 中也是合法的「值」，于是问题出现了：NULL 会被聚合函数忽略。如果一张表只有一行且该行值为 NULL，那么针对该表的 GROUP BY 查询中 COUNT 会返回什么？按定义，GROUP BY 与 COUNT 结合使用必然返回大于或等于 1 的值，可值被 COUNT 忽略时结果又如何？下面是揭示 NULL 分组悖论的示例（用 COALESCE 替换 NULL 只为提高可读性）：插入 5 个 NULL 后，count(name) 对 NULL 分组返回 0，而该分组实际有 5 个成员。

运行结果

「分组独一无二」这条公理也存在悖论：SQL 结果集和表更适合称为多重集合（multiset）或「袋」（bag），因为它们可以包含重复的行，也就可以返回包含重复分组的结果集。用 UNION ALL（多重集合运算，会两次调用 GROUP BY）合并两个 GROUP BY 查询即可看到重复分组；若改用集合运算 UNION，则不会出现重复分组。同理，把分组的具体化结果与另一张表做笛卡儿积，也会得到重复的分组。作者称这只是部分悖论（partial paradox）：独立的 GROUP BY 查询本身都符合分组定义，只有把两个 GROUP BY 结果集合并成多重集合时才会出现重复。

A.2 窗口函数

弄明白 SQL 分组概念和聚合函数用法后，窗口函数就很容易理解：与聚合函数一样，窗口函数也对指定的行集（分组）执行聚合操作，但不是为每个分组返回一个值，而是返回多个值（每个细节行一个值）。要对其进行聚合的行分组被称为窗口（window）。同一个概念，DB2 称之为联机分析处理（OLAP）函数，Oracle 称之为分析函数，ISO SQL 标准称之为窗口函数，本书统一使用「窗口函数」这一术语。

B.2 通用表表达式

为了克服子查询的一些局限性，引入了 CTE（通用表表达式），但它最著名的功能是能够编写 SQL 递归查询——实际上，引入 CTE 的主要目的就是让 SQL 支持递归。下面的示例结果与前面的子查询版本相同，同样执行双重聚合：使用 WITH 子句引入派生表（在括号内指定列名），并把生成派生表的查询放在括号内；如果要同时定义多个派生表，可以用逗号分隔，并把派生表的名称写在生成它的查询前面（这与在 SQL 中指定别名的方式相反）。由于内部查询是在外部查询之前定义的，CTE 在很多情况下可读性更高，便于逐一研究查询中的各个元素、弄明白查询逻辑；当然可读性高低取决于具体情况，有些情况下子查询反而更易读。

递归 CTE 的结构是「锚定成员 + UNION ALL + 递归成员」：锚定（anchor）查询位于 UNION ALL 之前，用来初始化虚拟表第一行的值；递归成员引用该虚拟表自身，反复产生后续行。下面的查询用递归 CTE 计算前 20 个斐波那契数，下一个斐波那契数为当前斐波那契数与前一个斐波那契数之和——这里用「当前数 + 前一个数」两列来模拟 LAG。关键字 RECURSIVE 在 MySQL、Oracle 和 PostgreSQL 中必不可少，但在 SQL Server 和 DB2 中是可选的；index1 列在计算斐波那契数时并没有用到，包含它只是为了简化在 WHERE 子句中指定返回行数的工作。在递归 CTE 中 WHERE 子句至关重要，没有它查询将不会终止（本例中若删除该子句，RDBMS 很可能在数字大到超出相应数据类型的范围时引发溢出错误）。此外，CTE 定义一次后可在同一查询中被多次引用，而派生表每引用一次就要重复书写一遍；嵌套大量子查询时可读性会急剧下降，因为后续查询层中各种变量的含义将晦涩不明，而 CTE 垂直地排列各个元素，让人更容易弄明白这些元素的含义。

MySQL 说明：MySQL 自 8.0 起才支持 CTE 与递归 CTE，且递归 CTE 必须写 with recursive；查询中要指定最大递归深度时应使用会话变量 cte_max_recursion_depth。

无法确认：源文本中递归成员写作 from anchor，但同一段中定义的 CTE 名为 workingTable，anchor 并非该片段中出现过的名称，此处疑为抽取时的讹误。

B.3 小结

派生表的使用极大地拓展了 SQL 的功能，本书很多地方都用到了子查询和 CTE，因此弄明白它们的工作原理至关重要，同时必须掌握它们各自的独特语法。目前本书涉及的 RDBMS 都支持递归 CTE，它提供了众多额外的可能性，是最重要的 SQL 扩展之一。
