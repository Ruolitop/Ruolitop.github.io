1. 环境准备

1.1 安装 Node.js

Hexo 8.1.1 要求 node >= 20.19.0，装 Node 22/24 LTS（.msi，确认勾了 Add to PATH）。装 18 或更早，npm install 会报 EBADENGINE。

装完还是旧版本 → where node 看在跑哪个，卸载重装。

1.2 安装 Git

hexo deploy 底层用 Git 推送。到 git-scm.com 下载 Windows 版，一路下一步，Adjusting your PATH 保持默认（让 Git 能在命令行调用）。

1.3 注册 GitHub 并建仓库

GitHub Pages 只有名字恰好等于 <用户名>.github.io 的仓库才发布到根域名。

  1. github.com 注册（假设用户名 zhangsan）。
  2. 右上角 + → New repository。
  3. Repository name 填 zhangsan.github.io；Public；不要勾 Add a README file、不选 .gitignore——保持完全空仓库。
  4. Create repository。

1.4 Git 身份与 SSH 密钥

GitHub 早已不支持密码推送，用 SSH 免密。

私钥 id_ed25519 绝不能外传；公钥粘到 GitHub：头像 → Settings → SSH and GPG keys → New SSH key。

必须用 SSH 而非 HTTPS：实测 HTTPS 推送被连接重置（Recv failure: Connection was reset）。所以 deploy.repository 写 git@github.com:...。

3.2.4 Markdown 渲染器与公式

两个坑：

  • 缩进层级：name / enable / options 必须嵌套在 plugin: 之下。平铺写法 YAML 能解析、构建也正常，但渲染器内部 checkPlugins() 会判定整条不合格、用 continue 跳过，于是 options 静默失效。
  • 取值：strict: 'warn' 不要写 false（会把不兼容写法提示全静音）；throwOnError: true 必须开——解析失败时插件会把原始 LaTeX 原样吐到页面、构建过程一声不吭。

改完核实：node tools/verify-plugin-options.js

3.2.7 Algolia 搜索凭据

三条铁律：

  1. apiKey 必须是 Search-Only Key——它会被明文写进每个页面的 JS 下发给访客，填成 Admin Key 等于把写权限公开。

  3. 这段属于根配置，不属于主题配置——主题读 config.algolia，写进 _config.butterfly.yml 不生效。

3.2.8 Deployment

3.3 主题配置 _config.butterfly.yml

一千多行，只需关心下面十几段。原则：先看默认值能不能接受，不能接受再改。

3.3.1 导航栏与菜单

语法 显示名称: 链接 || Font Awesome 图标。写成 名称||图标: 再缩进子项即下拉菜单；行首 # 临时隐藏；链接以 / 开头表示站内。

3.3.2 横幅与全局背景（本项目最大的改造点）

本站视觉重点：全站横幅透明，透出全局背景图。

坑一：不同页面读不同的键。

页面 读哪个键
首页 index_img
归档页 /archives/ archive_img
单个标签页 /tags/xxx/ tag_img + tag_per_img
单个分类页 /categories/xxx/ category_img + category_per_img
标签 / 分类总览页 /tags/、/categories/ default_top_img
有 cover 的文章页 cover
无 cover 的文章页 default_top_img

只设 tag_img / category_img，漏掉两个总览页走的 default_top_img，这两个页面会露默认浅蓝块。

坑二：值留空等于没设。 空值（null）时主题不生成内联 style，页面回落 CSS 默认色。必须显式写 transparent。

想让内容直接顶上去（连横幅空白都不要），把 disable_top_img 改成 true（只剩 60px 导航条）。

3.3.3 代码块

⚠️ theme 是枚举值，写错会让整站失去样式：填非法值（如 macStyle），stylus 编译失败但不中断构建，index.css 变 0 字节。每次构建后看一眼 index.css 大小。

3.3.4 副标题（首页打字机效果）

source 只能填数字，不能填网址。 模板 subtitle.pug 是 case source / when 1/2/3，编译成严格相等（===）的 switch。填网址字符串永远匹配不上数字 3，落 default：不请求任何接口、只显示 sub 兜底、不报错。而且 #subtitle 是空 <span>，内容全靠 JS 填——出问题时观众看到的是"什么都没有"。

3.3.5 文章卡片与目录

3.3.6 数学公式

per_page 必须为 true：① 主题 CSS 有 .katex { display: none }，靠 JS 加 .katex-show 才显示；per_page: false 时脚本只在写了 katex: true 的文章加载，漏写公式的文章公式全隐形。② 主题 showKatex() 选择器是 #article-container .katex——容器之外的公式元素永远拿不到 .katex-show。所以摘要、搜索索引里的公式必须整体替换成纯文本（本项目用 scripts/clean-post-desc.js）。

Markdown 写法：行内 $...$；独占一行 $$...$$ 且前后各占一行。禁用 MathJax 的 \( \) \[ \]；公式内不能出现中文标点；行内公式里不能写双大括号（会被 Hexo 当模板变量替换成占位符，内容丢失、页面乱码）。

3.3.7 搜索（Algolia）

主题配置只需一行：

设为 algolia_search 后主题自动把搜索按钮插到导航栏最前（#search-button 本就在 #menus 内）。凭据写在 _config.yml 的 algolia，不在这里。

配置流程：algolia.com 注册免费账号 → Create Application（选区域如 Hong Kong）→ Create Index（首次上传会自动创建）→ Settings → API Keys 抄三个值（Application ID→appId、Search-Only→apiKey、Admin→adminApiKey）→ 每改文章都重传：npx hexo algolia → 部署后点搜索按钮验证。

不想用搜索：删掉 _config.yml 整个 algolia 块，并把 search.use 留空。
限制：Algolia 免费版单条记录上限 10,000 字节，本项目只索引正文前 3000 字符——很靠后的关键词搜不到，是方案固有限制。

3.3.8 字体

font_family 是候选列表，从左往右取第一个可用的，自托管字体名要排最前。两套自托管字体定义在 source/css/custom.css：

用途 文件 @font-face 名 大小
正文 source/font/PingFang 简体.woff2 PingFang 简体 1.12 MB（子集版）
代码块 source/font/consola-1.woff2 Consolas Web 43.6 KB

四条经验：① font-weight 只写 normal（写区间会让加粗失效）；② 代码字体栈里拉丁字体必须排在中文前面；③ @font-face 名不要和系统字体重名；④ 中文正文字体建议子集化（全字集 10.4 MB，tools/subset-font.py 压到 1.12 MB）。

3.3.9 图片灯箱

⚠️ 值必须是小写 fancybox——主题内部有大小写敏感的资源映射表，写成 FancyBox 会解析出 undefined，页面生成 <script src="/">，浏览器把首页当脚本下载报 Unexpected token '<'，灯箱静默失效。

3.3.10 全站资源自托管（CDN）

默认走 jsDelivr，一旦访客网络不可达：

资源 加载失败后果
katex（CSS） .katex 永远 display: none，公式整段消失且不报错
algolia_search（JS） 搜索按钮点了没反应，控制台一行 Algolia search client not found!
typed（JS） 副标题永久空白（连兜底都不显示，见下）
katex_copytex 只影响"复制公式"

typed 特别危险：副标题逻辑是"先取到 typed.js 才渲染"，btf.getScript(url).then(...) 没有 catch，取不到就永久空白。

即 CDN.option 的键直接覆盖 asset 同名键。

仍走 CDN 的（Font Awesome、fancybox、两个特效脚本）不影响核心功能，可先不管。

3.3.11 样式注入点与其它开关

head 插到 </head> 前、bottom 插到 </body> 前——给主题"打补丁"的官方途径，升级主题不会覆盖。其它按需调：avatar、footer、aside、anchor、wordcount、error_404、mermaid、display_mode、activate_power_mode。

3.4 自定义样式 source/css/custom.css

通过 inject.head 的 <link> 引入；.css 不经 stylus 处理，原样拷贝。用途：定义自托管字体（见 3.3.8）、微调主题样式。怎么知道改哪个选择器：浏览器 F12 → 箭头点元素 → Styles 面板看规则与来源，把要覆盖的写进 custom.css。

3.5 站点脚本 scripts/

根目录 scripts/*.js 被 Hexo 自动加载，不用声明。本项目 clean-post-desc.js 挂在 after_post_render，提前算好 postDesc（卡片摘要）和 contentStripTruncate（Algolia 索引正文）——解决 KaTeX 三层内容（MathML / annotation / 视觉层）被拼成"公式三遍 + 露原始 LaTeX"的问题。正文里的 MathML 不受影响。别删。

3.6 改完配置的固定动作

第 1 步不能省：Hexo 把渲染结果缓存在 db.json，hexo generate 不会因主题配置变化让旧缓存失效——"配置改了、页面没变化"是新手最易被卡的假象。

5.3 在文章里插图片

开 post_asset_folder 后推荐相对路径：图片放 source/_posts/文章名/图片.png，正文单独占一行写图片引用、括号里只写文件名。hexo-image-link 会解析成正确地址。也可集中放 source/img/，用以 / 开头的绝对路径如 /img/website-background.jpg。

⚠️ 示例用行内代码而非三反引号代码块，是刻意的。hexo-image-link 用一条正则无差别扫描全文、不区分代码块；它执行时三反引号代码块已被高亮成 HTML，贪婪正则会把 </span> 吞进"路径"，误判成资源引用、把示例改成带 span> 的乱码。规避：用行内代码，或写成 /img/x.jpg 这种以 / 开头的形式。

5.4 公式

行内 $a^2 + b^2 = c^2$；独占行公式前后各留一空行：

β^(k)=(X′X+kI)−1X′y\hat{\beta}(k) = (X'X + kI)^{-1}X'y β^​(k)=(X′X+kI)−1X′y

四条红线：① $ 两侧带空格不被识别；② $$...$$ 不能挤在同一行；③ 公式里不能出现中文标点；④ 行内公式里不能写双大括号。

5.5 常用标签

Butterfly 的富文本组件用 % 包起来的开始 / 结束标记（如 note、hideToggle、tabs、link、btn、label、gallery、timeline、mermaid）。不确定语法去 Butterfly 文档 搜。

⚠️ 想展示标签写法，必须用 raw / endraw 包起来——Hexo 在 Markdown 渲染前就处理标签，连代码块里的内容也会执行，不包会被真的执行掉。

check-math.py 公式是否真的渲染（裸 $、裸 TeX、MathJax 定界符、KaTeX 资源、摘要原始 LaTeX、占位符泄漏）
check-banner.py 横幅透明是否全站生效
check-search.py 搜索链路（凭据、apiKey 是否误填 admin、索引记录数 --live、url 是否占位值）
check-subtitle.py source 是否合法数字枚举、产物是否有对应调用、typed 是否还走 CDN
check-font-web.py 换字体前跑：OTS 合规、空白字形、等宽性
subset-font.py 中文字体子集化
serve-local.py 本地预览（补字体 MIME）
verify-plugin-options.js 验证 KaTeX 的 options 透传了

每次上线前跑这四个（退出码 0 通过）：

7. 线上部署

7.1 首次部署

前置：空公开仓库 <用户名>.github.io；ssh -T git@github.com 成功；_config.yml 的 url / deploy.repository / branch: main 已改；已 npm run build。

首次会创建 .deploy_git/（别删）并推送，较慢。

开启 Pages：仓库 → Settings → Pages → Source 选 Deploy from a branch → Branch 选 main、目录 / (root) → Save。

7.2 hexo deploy 做了什么

读 deploy 配置 → .deploy_git/ 不存在就 git init 配 remote → 把现有 public/ 整个拷进 .deploy_git/ → commit + push。

推论：① hexo deploy 不会重新生成，改了文章忘了 build 就部署旧内容；② 想重建远端历史：删 .deploy_git/ 再部署。

7.3 验收线上

等 1～2 分钟，强刷（Ctrl + F5）访问 https://<用户名>.github.io，逐项查：首页有样式（非纯文字）；/tags/ /categories/ /archives/ 能进；文章公式与代码高亮正常；搜索能搜到并点进正确网址（非 example.com）。

7.4 日常更新流程

第 2、4 步可合并：npx hexo deploy --generate。进阶可在 package.json 加 "publish": "hexo clean && hexo generate && hexo algolia && hexo deploy"。

7.5 自定义域名（可选）

  1. source/ 下建无扩展名文件 CNAME，内容只有域名一行（如 blog.example.com）。
  2. 域名服务商加 CNAME 记录指向 <用户名>.github.io。
  3. GitHub → Settings → Pages → Custom domain 填同域名 → 勾 Enforce HTTPS。
  4. _config.yml 的 url 改成 https://blog.example.com，重走完整流程（npx hexo algolia 不能省——域名变了索引链接要刷新）。

9. 注意事项

9.1 安全

  • apiKey 必须是 Search-Only Key，明文下发每个页面；填成 Admin Key 等于公开写权限。
  • adminApiKey 别提交公开仓库，可用 ALGOLIA_ADMIN_API_KEY 环境变量替代。
  • SSH 私钥（~/.ssh/id_ed25519）绝不外传，只有 .pub 公钥能给别人。

9.2 必知的操作习惯

  1. 改主题配置后一定清缓存（npm run clean）——"改了没反应"的头号根因。
  2. 每次构建数 ERROR、看 index.css 大小——判断构建健康唯一可靠信号。
  3. front-matter key: value 冒号后必须有空格——写错不报错，只让那篇静默沿用旧内容。
  4. 写公式记四条红线（见 5.4）。
  5. 改了正文就重传搜索索引，否则线上搜不到。
  6. 别手改 public/，下次生成会被覆盖。

9.3 项目维护

事项 说明
备份源码 默认只有 public/ 被推到 Pages；想备份 source/、配置、scripts/ 需另建仓库
别删 scripts/、tools/ clean-post-desc.js 参与渲染，删了摘要与索引出问题
themes/ 保持空 主题来自 node_modules
别提交 node_modules/、public/ 73 / 105 MB，都能重新生成
依赖与主题升级 katex 两端版本必须一致（overrides 管）；升级主题后对比官方默认配置补新增项
