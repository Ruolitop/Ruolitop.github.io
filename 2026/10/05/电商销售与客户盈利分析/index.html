电商销售与客户盈利分析

发表于2026-10-05|更新于2026-10-05|数据分析
|总字数:3.4k|阅读时长:12分钟|浏览量:

把一份「年营收 1.77 亿美元、13.8 万订单」的杂乱电商数据，变成一套口径统一、可一键复验、能量化折扣风险的分析体系。

_数据来源：Kaggle E-Commerce Sales Dataset（合成数据）。本项目为个人分析项目。

技术栈：Python 3.12 · pandas · NumPy · Tableau1

项目结构

结论

  • 最佳折扣区间 0%–20%：覆盖 102,091 单（占总单量 74%），利润率仍稳定在 42.9%–51.9%，是投放效率最高的区间
  • 利润红线预警 35%–40%：亏损订单在此区间首次出现
  • 严重亏损区>45%：3,796 单（仅占总单量 2.75%）中 1,083 单亏损，亏损率 28.5%
  • 55% 以上直接击穿盈亏：766 单净亏 −＄72.8K

利润集中，头部依赖明显

  • Electronics 销售额最高（＄41.15M）但利润率最低（34.28%），属「走量不赚钱」
  • Jewelry / Home Appliances 以 40%–41% 利润率贡献 ＄28.2M 利润
  • 销售额前 3 类目（Electronics、Jewelry、Home Appliances）合计占总销售额 47.6%

配送时效显著拖累长尾体验

  • 提前送达 3.795 天、准时 4.531 天，均优于承诺的 5 天
  • 但延迟订单平均 6.833 天，超均值 5 天
  • 长尾延迟不仅引发差评，更直接导致「顾客流失」

客户价值分布极度长尾

  • 销售额与利润呈强正相关，头部单笔净利可达 2.5 万美元
  • 但极少数「单笔巨额亏损」客户（CUST-012880 亏 −＄1,117）拉低整体质量

口径治理

  • 两表金额不可混用:sales_customer（订单级）与 order_items（行级）的金额在约 8.13% 的订单上不一致。

处理：金额全部取自 order_items 列，属单一基准货币口径，可安全横向比较；JOIN 订单表时只取维度列、不取任何金额列，从结构上杜绝误拼。

  • 利润率必须加权，不能平均:
    一律用 SUM(profit) / SUM(net_sales) × 100，禁止对比率列求 AVG——否则小额订单与大额订单被同等加权，结果失真。

  • 利润恒等式:
    实测确认：profit = net_sales − product_cost − shipping_cost，138,116 行零偏差。

  • 跨币种金额不可加总
    7 种货币下，跨州/跨地区金额列不可横向相加，但利润率、订单数等比率指标跨币种安全。

维表与事实表的人数不一致

customer_master 有 25,000 名客户，而 sales_customer 只出现 24,911 名——即 89 名客户从未产生订单。计算复购率、客户终身价值等指标时，若以维表为分母会得到偏低的数值。本项目所有客户级指标均以有订单的 24,911 人为口径。

数据预处理

数据处理脚本为 data_preprocessing\data_preprocessing.ipynb，处理后的文件保存在目录 data\clean_data。

缺失值

在原始数据中有 9 个字段存在缺失。预处理原则：先判定缺失语义，再决定处置方式：

  • return_status / return_reason：缺失即业务上的「否」。 实测源数据中 return_status 仅两个取值（Returned 9,462 条、缺失 128,654 条），且凡标记为 Returned 的行都有有效退货原因。缺失与「未退货」是一一对应的，因此填充为语义显式的 Not Returned / Not Applicable，而非当作数据错误。
  • coupon_code：先验证缺失与折扣无关，再填充。 填充前做了分组检验：按 coupon_code 是否为空对 discount_amount 分组统计，确认未用券订单的折扣额均值与整体一致，说明缺失代表「本单未使用优惠券」，而非「用了券但编码丢失」。据此填 No Coupon。
  • campaign_name：无法确证语义，故填「未知」而非「无」。 与 coupon_code 不同，这里的缺失在各营销渠道中的分布比例相近（交叉表核验），无法有把握地解读为「没有营销活动」。因此保守填充为 Unknown Campaign 而非 No Campaign——这是刻意保留不确定性，而非消除它。这一区分对下游分析有实际影响：若误填为「无活动」，会低估自然流量订单的占比。

冗余与一致性检查

预处理阶段同时完成了以下检查，结论均为无需处理：

  • 重复行：4 张基表的完全重复行数均为 0（duplicated().sum()）。
  • 主键唯一性：sales_customer.order_id、order_items 的 (order_id, product_id) 组合、product_catalog.product_id、customer_master.customer_id 均唯一。
  • 文本规范化：对 customer_city 与 customer_state 做小写 + 去首尾空格的规范化，唯一值数量均无变化，说明源数据不存在大小写或空格导致的重名（如 New York / new york）。

关键口径

以下四项结论均经过 SQL 全量校验：

  1. 利润恒等式：profit=net_sales−product_cost−shipping_cost\text{profit} = \text{net\_sales} - \text{product\_cost} - \text{shipping\_cost}profit=net_sales−product_cost−shipping_cost

  2. 净销售额：net_sales=gross_sales−discount_amount\text{net\_sales} = \text{gross\_sales} - \text{discount\_amount}net_sales=gross_sales−discount_amount 不成立

    全部 138,116 行都不相等，每单多出约等于 tax_amount 的部分（均值 122.46）

  3. 利润率：∑profit/∑net_sales×100\sum \text{profit} / \sum \text{net\_sales} \times 100∑profit/∑net_sales×100，单位为百分数

  4. 币种：7 种币种（USD / GBP / EUR / CAD / AUD / INR / AED）与国家一一对应，跨地区只比较比率型指标，绝对金额仅在单币种内可比
